# 0.7 内存分析与开发工作台

本版本面向 Windows x64 本地 VS Code。新增功能不会自动改写 CMake、链接脚本或应用代码；诊断组件由用户主动复制并接入。运行监测处于实验阶段，实机验证见 verification-0.7.md。

## 静态分析

成功构建后后台读取当前目标 ELF，不影响构建、烧录和调试是否成功。侧栏进入「内存分析」，四个页签分别为概览、布局与符号、构建对比、运行监测。区域卡片可过滤符号；树图可按区域、库、目标文件、符号下钻，通过面包屑返回。符号表每页 100 行，支持搜索/排序/区域及代码数据过滤。源码位置只有落在当前工程且可验证时才可打开，否则复制地址。

MAP 来自当前 CMake File API 目标的链接参数，支持 -Wl,-Map=…、-Map …、-Xlinker -Map -Xlinker …。不扫描最新 MAP。复杂响应文件、不受支持的链接参数或文件缺失会降级，提示用户显式提供目标 MAP 参数。可手动加入以下片段（将 firmware 替换为真实目标）：

    target_link_options(firmware PRIVATE "-Wl,-Map=firmware.map")

MAP 的输出目标、时间及所有分配段的地址/大小都必须与 ELF 相符，读取中变化的文件不会用于归因。此匹配不是 MAP 与机器码内容的密码学证明：同布局的手工替换 MAP 无法仅凭段表识别；不要复用其他构建生成的 MAP。ELF 在分析前后均检查 SHA-256。

容量优先取 MAP Memory Configuration，再取实际构建输入中可解析的 MEMORY 字面量。表达式求值失败或区域重叠时不猜容量。区域用量是分配地址区间的并集：初始化数据同时计入 RAM 运行地址和 Flash 加载地址，NOLOAD 不计加载镜像；堆栈预留显示为区域用量的子集，对齐空洞独立显示。符号排行不参与区域总数求和，别名及重叠归因只计一次。未知区域不显示百分比。

构建对比按工程/Configure Preset/Build Preset/配置/目标隔离，默认与上一次成功分析比较，可固定基线。保存最多 20 份 + 1 个基线，大报告受 96 MiB 缓存预算限制提前裁剪；单目标缓存最大 120 MiB，内存中最多缓存 3 组历史。缓存是报告用途，不能替代构建证据或硬件授权。

JSON 包含完整分析数据；CSV 导出完整符号表并转义公式前缀；HTML 自包含，包含区域摘要和最大的 1000 个符号。导出采用工程相对路径，工程外源码不启用跳转。MAP/ELF 诊断消息仍可能包含本机文件名，外发前可检查。

## 0.7.1 内存空间浏览器与 HEX

区域采用固定配色，色块仅显示短文件名，完整路径保留在悬停详情。点击区域/文件/符号逐层进入；在色块上向上滚轮连续放大也会进入该项目。工具栏 + 连续放大默认选择当前层最大的可进入项目。通过横向面包屑、返回上一级或全部分区返回；列表入口提供键盘可达替代操作。

符号层直接显示当前 ELF 的十六进制内容：16 字节/行、ASCII、运行地址 VMA 与加载地址 LMA、256 字节/页。输入以 0x 开头的运行地址可定位并选中具体字节；点击字节显示 HEX、十进制和二进制。符号明细表的 HEX 按钮可直接查看被树图裁剪的小符号或别名。

这里是磁盘上的固件字节，不是芯片当前 RAM。BSS、NOLOAD 显示「无固件字节」，不会虚构零值；初始化 data 展示 ELF 初始化镜像及不同的 VMA/LMA。未归因填充/预留只提示布局入口，不猜测其内容。无符号或段边界不可验证时不启用字节读取。

只接受当前分析的符号 ID；Webview 无法指定文件路径。读取器校验 ELF SHA-256、32 位小端 ARM 类型、段表及符号边界，最多返回 256 字节。报告过期、工程切换、文件变化或延迟回复会被丢弃。首次打开需校验文件摘要，后续页复用文件身份缓存；不读取整个符号到 Webview。支持深/浅/高对比度，窄面板只在 HEX 表内部水平滚动。

## 0.7.2 缩放、动画与大视图

- 鼠标滚轮向上放大，向下缩小；到 100% 后继续缩小返回父层。工具栏减号遵循相同逻辑，HEX 页也可通过减号返回符号。Alt+← 返回，普通视图 Escape 返回；大视图 Escape 先退出大视图。
- HEX 内普通滚轮滚动字节表，Ctrl+向下滚轮返回符号；无需用滚轮时可一直使用可见的减号/返回按钮。根总览已完全缩小时不拦截向下滚轮。
- 连续缩放有 100–220 ms 图形过渡，进入/返回有约 260 ms 的淡入缩放。系统启用减少动态效果时自动关闭。层级切换后的同向惯性短暂抑制，反向缩小不受限制。
- 分区详细指标默认折叠，摘要仍显示已用量和已知占用率；可展开查看全部容量、剩余、预留和空洞。大视图保留导航和操作，将编辑区空间交给图表/HEX，退出恢复页面滚动位置。

## 独立功能配置与迁移

运行命令「配置扩展功能」，创建并打开 .vscode/stm32-easy.features.json。VS Code JSON Schema 提供字段补全和验证。原 .vscode/stm32-easy.json 的 schemaVersion 1、工具选择、CLion、clangd 与硬件确认记录继续保留。新增配置没有默认启用 RTT，不自动迁移到用户固件。

示例（所有地址、容量、固件标识必须来自你的实际工程；下列仅为格式示例）：

    {
      "version": 1,
      "memory": { "budgets": { "RAM": 65536 } },
      "runtime": { "enabled": false, "searchBytes": 256, "channel": 0 },
      "debug": { "core": "m4", "rtos": "FreeRTOS", "heapImplementation": "heap_4" },
      "tools": {}
    }

预算单位为字节，仅告警。常规配置请使用运行监测页的“一键配置监测”：从当前已验证 ELF 读取 RTT 地址和可选导出标识，自动模式在每次连接前刷新地址。旧版组件要求输入与 `stme_init` 一致的 firmwareId 一次。仅手动集成时才需要编辑 `runtime.address` 和 `firmwareId`。H7 必须确认缓冲区位置与 MPU/cache 配置后才能启用；自动流程不会替用户设置 `cacheCoherent`。工具要求为精确版本字符串，tools 支持 armGnu/cmake/ninja/openocd；差异显示在体检中。本机工具绝对路径和串口选择不写入共享文件。

## 无固件组件的暂停快照

只读取本插件启动或附加的 Cortex-Debug 会话；目标已暂停时读取 SP、MSP、PSP、PC。不会自动暂停运行中的程序，不通过 GDB 调用目标函数。debug.core 配置匹配当前核心后，M3/M4/M7/M33 读取 CFSR/HFSR 并解码常见异常，M0 不读取这些寄存器。

可选 debug.stack 为 { "low": 数值, "high": 数值, "pointer": "msp" 或 "psp" }，仅在指针落入用户核实的区间时给出向下增长栈的深度；未配置时明确显示未知。FreeRTOS + heap_4/heap_5 在调试符号可读时尝试读取 xFreeBytesRemaining 与 xMinimumEverFreeBytesRemaining，缺失或不一致会说明原因；不遍历未知版本 TCB，不执行分配器。暂停在分配器临界更新中可能得到不完整统计，优先在稳定断点读取。

附加调试要求当前目标已有成功构建 ELF，并验证文件摘要。附加不能证明已运行固件与 ELF 相同，须由开发者核对；增强 RTT 会额外核对显式固件 ID。

## 可选诊断组件与 RTT

在运行监测页选择「获取固件组件」，选定目录后复制到新建的 stm32-easy-monitor 文件夹，打开接入说明。不会覆盖已有目录，也不会自动修改用户工程。组件包含 C/H、CMake helper、裸机/FreeRTOS 接入说明与 H7 的 NOLOAD 段模板。

默认每秒堆采样、每 5 秒任务栈水位采样，使用 2048 B RTT 环和 2048 B 帧缓冲，最多 8 个任务；可用宏调整。无需 malloc，无中断采集，无栈填充改写，非阻塞写入；溢出、序号缺口、固件 ID 不匹配、重启和无新样本均可见。任务名和标量在调度锁内复制，随后释放；任务快照有独立采样时间。任务太多或帧太大显式提示。

FreeRTOS 10.3.1 已做本地编译验证；10.x/11.x 其他组合尚未验证。heap_4/heap_5 的完整指标要求 STME_HAS_HEAP_STATS=1 与对应 vPortGetHeapStats；heap_5 总容量由应用明确给出。任务容量由注册接口提供，不知道总容量时不计算使用率。裸机堆由应用回调提供，栈深是采样值/采样峰值，并非两次采样间真实峰值。完整 API 见组件 README。

「连接并监测」只启动一个受管 OpenOCD；不发送固件下载、halt 或 reset 命令，脚本本身仍可能改变硬件状态，连接前显示脚本指纹和目标。15 秒内没有匹配样本则失败并清理。与已有调试共享探针；已有会话没有 RTT 时要求停止后重新启用。Tcl/RTT/GDB 只绑定回环地址并校验进程归属。关闭独立监测面板会停止服务器；调试附带监测时关闭面板保留调试会话，停止调试释放全部端口。

曲线最多保留 10 分钟/6000 个样本，可暂停显示、选择时间范围、导出 JSON；保留最新 60 条可键盘访问的采样明细。暂停显示不会停止采集。丢包区间显示断点。H7 缓冲区需处于探针可访问且非缓存的区域；C5/U5 只访问当前调试域允许的数据，不支持的工具组合直接失败。未实现逐次 malloc/free 跟踪、跨安全域、双核联合分析或完整泄漏定位。

## 开发辅助

- 工程体检：工具、缓存、补全配置覆盖、依赖能力、精确版本差异和脱敏导出。探针分为 PnP 发现、Windows 驱动状态、显式目标连接三个证据层；驱动正常不等于调试接口可打开。
- 串口：端口/波特率本机记忆、UTF-8/HEX、时间戳、过滤、30 项发送历史、日志保存；窗口内保留最多 2000 块/约 2 MiB 字符，不是无限录制。成功打开后才允许发送，不主动拉高 DTR/RTS。关闭面板关闭串口进程。
- CubeMX：监听 .ioc 与 cmake/stm32cubemx/CMakeLists.txt，忙碌时延后提示；用户选择重新配置后由既有补全集成更新。不会抢占构建。
- 调试辅助：独立附加、用户提供 SVD、FreeRTOS 线程、原生暂停/继续/复位入口。SVD 仅允许工程内路径。
- 面板：离线 ECharts 6.1.0，深/浅/高对比度、中英文、320px/760px/1280px，分页避免向 Webview 一次发送全部符号。

构建工具 vsce 4.1.0 需要 Node.js 22+；这不改变插件运行所需的 VS Code 版本。

## 0.7.3：一键配置监测

运行监测页选择“一键配置监测”。已有组件从当前已验证 ELF 自动识别地址及导出标识；没有组件时，标准 CubeMX 工程可预览后自动接入并编译。之后通过侧栏烧录新固件，再连接。高级 JSON 配置仍可使用，自动模式每次连接刷新地址。详细适用条件、内存开销和移除步骤见 [中文组件说明](../resources/firmware/README.zh-CN.md)。

## 0.7.5：堆采样频率

先停止监测，再选“堆采样频率”：1 / 2 / 5 / 10 Hz。插件预览当前目标编译宏改动，确认后应用并编译，用户烧录后生效。任务栈详情保持 5 秒，避免同步提高扫描开销。实际接收率由固件时间戳计算，已计入丢失采样影响；高优先级任务、探针读取带宽与丢帧均可能使实际值低于请求值。图表界面合并刷新约 5 次/秒，但保留收到的全部样本至有界历史；不生成重复数据。
