# 国际化维护

扩展激活时读取 `vscode.env.language`：`zh`、`zh-*` 使用简体中文，其他区域使用英文。修改 VS Code 显示语言后按宿主提示重启即可生效，不增加独立语言开关。

- `package.nls.json`：英文命令名、扩展描述与设置说明。使用稳定的命令 ID / 设置 ID 作为键，不依赖数组下标。
- `package.nls.zh-cn.json` 和 `package.nls.zh.json`：简体中文，以及其他中文区域的回退；两个文件保持一致。
- `src/i18n/en.json`：运行时英文词条，以现有中文原文为键；中文使用原文。翻译通过 `t('原文 {0}', value)` 显式调用，原文键不要拼接。
- `src/i18n.ts`：宿主语言选择、翻译、HTML 转义与安全的 Webview 词条序列化。
- `resources/workbench/i18n.js`：Webview 翻译器，使用宿主提供的同一份词条；遵守 nonce CSP，无网络请求。

工程名、路径、Preset、固件目标及外部工具原始输出只能作为参数传入，不能扫描替换用户内容。占位符替换只执行一轮，参数中的 `{0}`、HTML 或 `$&` 均保留字面值。模板 HTML 的翻译使用 `escapeHtml`，动态界面使用 `textContent`。

状态/消息中的内部命令 ID、操作阶段、修订号与配置字段不翻译。错误归类保持中英文兼容，恢复入口不会自动重试硬件操作。

执行 `npm test` 检查词条覆盖、原生扩展清单、占位符、语言回退和错误入口。执行 `npm run test:ui` 检查两种语言的实际 HTML/JS：深色、浅色、高对比度及 320px / 1000px 布局。
