# 支持范围与技术说明

## 平台与工程

支持 Windows x64、本地 VS Code 1.96 及以上版本、可信的本地文件工作区。工程需已有 CMakeLists.txt 和可解析输出目录的 Configure Preset。首轮硬件范围为 CMSIS-DAP（包括 DAPLink）与 SWD。

不生成 HAL 工程，不转换 Keil 工程，不替代 CubeMX。Linux、macOS、Windows ARM64、WSL、SSH、容器和 Web 版 VS Code 尚不支持。

构建方案对应 Configure Preset；构建预设对应 Build Preset，必须与方案兼容。不使用 Build Preset 时直接构建方案解析出的输出目录。切换方案或构建预设会使旧目标失效，配置后重新识别。多个固件目标需要明确选择。

## 文件与设置

插件不改写源码、Presets、CMakeLists、toolchain、链接脚本、.ioc、用户 OpenOCD 脚本或 .vscode/tasks.json、launch.json。CMake 自身按工程规则产生构建输出；构建目录还会包含插件的 File API 查询及依赖记录。

工程设置按工作区文件夹 URI 隔离，保存在扩展私有存储 projects 中。工具选择保存在 active，信任和硬件确认保存在 trust，操作锁保存在 operation-locks。保持 schemaVersion 1 及原有命令 ID。多窗口保存使用修订号检查，过期草稿不会覆盖另一窗口的新设置。

不清除 CMakeCache、不使用 --fresh。源码目录、生成器或编译器冲突时停止并说明，由用户检查工程预设和构建目录。不修改系统 PATH；工具路径只加入相应子进程的环境。

## 工具管理

工具检查结果由侧栏和设置页共享。已配置表示安装记录及文件可用，不等于检查过全部能力或目标硬件在线。重启后检查结果不冒充新一次检查结果。单项检查、安装和离线导入只处理选定工具。

工具安装清单固定版本、URL、大小及 SHA-256，不跟随 latest；VSIX 不附带大型工具包。Arm GNU、CMake、Ninja 和 OpenOCD 采用各自上游许可。选择外部程序前会确认来源；OpenOCD 检查不初始化目标。

已有工具可选择完整发行目录或 bin；Arm 工具需要库、GDB 和 binutils，OpenOCD 需要 scripts。OpenOCD 候选除 PATH 外还读取已有 CLion 配置，不扫描整盘。

支持显式 HTTP/HTTPS 代理和匹配固定清单的原始 ZIP 离线包。不支持 PAC/网页登录代理，不关闭 TLS 校验，不安装驱动。

旧的“配置 VS Code 工具路径”命令仍可使用，但并非工作台前提。它修改用户级 CMake Tools / Cortex-Debug 路径，应用前展示预览；恢复时保留用户后续修改。

## 构建与硬件动作

烧录与调试始终先保存和编译当前工程。编译失败、取消、源码或配置变化、产物缺失会阻止硬件操作。使用当前目标的 ARM ELF，而不是扫描目录中最新的文件。

硬件前校验依赖 Ninja 的实际输入、命令、GCC 依赖文件、链接脚本及 ELF 证据。无法可靠确定依赖时保留编译能力并说明硬件限制。非 Ninja、自定义 specs/sysroot/工具前缀、复杂 response 文件及部分汇编依赖不保证支持烧录调试。

默认按文件大小、修改时间及创建时间复用哈希；可用 `stm32Easy.verification.strictHashing` 强制重新读取，或运行“清除校验缓存”。此检查不构成任意 CMake 脚本的安全沙箱，也无法消除所有外部进程竞争。

首次烧录或调试确认工程、芯片与固件后，可选择“确认并记住”。工程构建选项、目标、芯片、脚本内容、探针参数或停 main 选项变化后重新确认。设置页可以撤销已有确认。工程外依赖按目录记住信任；自定义 cfg/tcl 属于可执行代码。

构建目录和硬件操作使用跨窗口互斥；工具变更与工作流在当前窗口互斥。不控制其他 IDE，请避免 CLion、CMake Tools 或其他窗口同时占用同一构建目录或探针。进程退出无法确认时保留锁并报告状态不确定，不自动清理其他进程的锁。

停止仅结束本插件拥有的作业或调试会话。已发生的 Flash 写入无法撤销，烧录中取消可能留下不完整固件。不自动 mass erase、不解除读保护、不更新驱动或探针固件。

## 调试与已知限制

原生调试依赖 Cortex-Debug 1.12.1 或兼容的 1.x；编译和独立烧录不依赖此扩展。插件持有 OpenOCD 服务，使用内存中的 external launch 配置启动原生调试，不写 launch.json。

当前 Windows GDB 调试要求源码和 ELF 路径为 ASCII。中文路径可编译和独立烧录，不会复制固件或修改工程来绕过调试限制。“调试会话已启动”不代表已停在 main，实际暂停位置看原生调试界面。

不后台连接探针；盘符、串口或工具检查成功不表示调试接口在线。历史烧录结果附时间。电机等执行器工程在硬件操作前应切断动力电源，仅保留控制板供电。

0.5.3 为 VSIX 测试版，未上架 Marketplace；真实烧录、main 断点、单步和变量显示尚未完成本轮验收。没有遥测或上传工程内容的实现。
